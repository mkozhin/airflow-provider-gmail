# Контекст: `airflow-provider-gmail`

Глоссарий домена. Названия здесь — канонические: в коде, тестах, docstring и ADR
используем именно эти термины, без синонимов. Складывается по ходу проектирования
(грилинг + `/domain-modeling`), а не выдумывается вперёд.

## Слои

- **Слой 1** — этот провайдер: Gmail → S3 / локальный диск. Знает про Gmail и про то,
  куда положить байты. Про формат файла (`.xlsx`, `.csv`) не знает ничего.
- **Слой 2** — разбор файла в таблицу. Вне провайдера. Самый нестабильный.
- **Слой 3** — загрузка таблицы в БД/S3. Стандартные провайдеры.

Границы проведены по скорости изменений, не по объёму кода. Подробно —
`docs/gmail-pipeline-layers-2-3.md`.

## Ядро домена

- **Выгрузка (export)** — одна настроенная труба «письма конкретного вида → хранилище».
  Ожидается несколько десятков независимых выгрузок; повторяющаяся логика — в провайдере,
  специфика — параметры DAG.
- **Письмо** — единица обработки. Идентифицируется **`message_id`**: опаковый id письма
  в пределах ящика (`users.messages.list` → `id`), hex-строка, безопасна для пути.
  Не путать с RFC-заголовком `Message-ID` и с `attachmentId`.
- **Вложение (attachment)** — MIME-часть с непустым `filename` и хотя бы одним источником
  тела (`attachmentId` **или** ключ `data` в `body`). Из вложений исключаются
  **inline-картинки** (inline И `image/*`). Inline не-картинки
  (PDF, xlsx) — остаются вложениями.
- **Манифест (`_manifest.json`)** — файл рядом с вложениями письма. Пишется **на письмо
  целиком, после всех его вложений**. Контракт со слоем 2 и (в S3) носитель состояния
  дедупликации. Схема — единая в плане, в `docs/gmail-pipeline-layers-2-3.md` и в тесте.
  Живёт как **глубокий модуль** `Manifest` (см. ниже), а не как inline-словарь.

## Окно поиска

- **Окно / `lookback_days`** — скользящее окно `after:<epoch>`. Календарные дни от полуночи
  опорного дня. `0` → только сегодня; `7` → восемь календарных дней. Окно — это
  фильтр по времени, **не** состояние обработки: `lookback_days` дедупликацией не является.
  Дефолт зависит от оператора: S3 — `7` (окно безопасно, есть дедуп), локальный — `0`
  (широкое окно без дедупа размножает доставку). См. `docs/adr/0001-delivery-contract.md`.
- **Опорный день (reference day)** — стабильная дата `DagRun`, от которой отсчитывается
  окно. Берётся из `context["data_interval_end"]`, а не из `date.today()`, — иначе окно
  уезжает между retry. **Календарный день берётся в `timezone` оператора**
  (`data_interval_end.astimezone(...).date()`), не в зоне расписания DAG. См.
  `docs/adr/0002-window-day-in-operator-timezone.md`.
- **`date_from` / `date_to`** — необязательный явный диапазон дат (день, в `timezone`
  оператора), заполняется из `dag_run.conf` при ручном backfill. Если задан хоть один —
  заменяет окно `lookback_days`; `before:` = полночь `(date_to + 1 день)`, чтобы день
  вошёл целиком. См. `docs/adr/0004-explicit-date-range-backfill.md`.

## Пути

- **`dt=YYYY-MM-DD`** в пути — дата **письма** (`internalDate`) в `timezone` оператора,
  **не** дата запуска. Несущая деталь дедупа: одно и то же письмо всегда ложится по
  одному пути `<base>/dt=<дата письма>/<message_id>/`, поэтому манифест находится между
  запусками. Дата запуска в пути не участвует.
- **`internalDate`** приходит из Gmail строкой (epoch в миллисекундах) — `int()`, /1000,
  затем в `timezone` оператора. Та же зона, что у окна (ADR-0002).

## Доставка и дедупликация

- **Доставка (delivery)** — передача вниз (в XCom) списка **полных путей** к манифестам
  писем, обработанных **в этом запуске**: S3 — URI `s3://<бакет>/<ключ>`, локально —
  абсолютный путь. Вниз уходят только эти пути, больше ничего. URI адресует объект
  только в паре с подключением потребителя — endpoint хранилища живёт в connection,
  не в URI.
- **Резолвер (resolver)** — публичная операция слоя 1 «список манифестов → плоский
  список полных путей вложений». Второй владелец знания о схеме манифеста (рядом с
  `Manifest`) и **официальный клиент контракта манифеста**: рекомендуемый путь для
  слоя 2, при котором тот о манифестах может не знать; прямое чтение манифеста
  слоем 2 остаётся поддерживаемым контрактом (см. Манифест). Чужой вход не чинит и не
  интерпретирует: дубликаты проходят как есть по количеству (под `pick="all"`
  сортировка по дате может их перегруппировать, если во входном списке они шли
  вперемешку — см. `pick`), отсутствующий или битый манифест — громкая ошибка, не
  пропуск.
- **`pick`** — правило выбора писем в резолвере. `all` (дефолт) — вложения всех
  манифестов, отсортированные хронологически по возрастанию `internal_date`
  (самое старое письмо первым; одинаковый `internal_date` — стабильный tie-break
  по входному порядку) (ADR-0008); `latest` — вложения **одного** письма с
  максимальным `internal_date` (сравнение как aware-моментов времени, tie-breaker —
  `message_id`); пустой `files` победителя отдаётся как есть, без fallback на более
  старое письмо.
- **`run_id`** — идентификатор `DagRun`, записавший манифест. Ключ различения:
  манифест **текущего** `run_id` (упавшая попытка) → отдать вниз, не качать; манифест
  **прошлого** `run_id` → не отдавать; манифеста нет → качать и отдать.
- **Дедупликация доставки** — только S3-режим, по манифесту + `run_id`. В локальном
  режиме её нет by design (`_read_manifest` всегда возвращает `None`). **Устранение дублей —
  задача слоя 1, а не потребителя**: внешняя система, читающая S3, не должна дедуплицировать,
  её дело — обработать то, что лежит (усиление ADR-0001).

## Модули (глубина, из грилинга `/improve-codebase-architecture`)

- **`Manifest`** — глубокий **чистый** модуль (`manifest.py`): содержимое + сериализация,
  без Airflow/S3/Gmail, без путей и таймзон. `build(...)` (принимает уже готовые
  `internal_date_iso` и `files[].path` — политику зоны/пути готовит вызывающий),
  `to_json()`, `from_json(raw: str | bytes)` (принимает `str` — уже декодированный
  `S3Hook.read_key()` — и `bytes` локального чтения; `bytes` обязаны быть каноничным
  BOM-less UTF-8: любая порча — не-UTF-8, ведущий BOM, битый JSON, нарушение схемы —
  даёт единый `ManifestError`, единообразно для S3 и local),
  `from_s3(hook, bucket, key)` — duck-typed шов чтения
  из S3 (hook инжектится, `S3Hook` не импортируется, поэтому инвариант «без S3»
  держится): обёртка над `read_key` + `from_json`, единая точка контракта порчи для
  всех трёх S3-чтений. Схема контракта со слоем 2 живёт в одном определении.
- **`FileEntry`** — плоский dataclass `(name, size, path)`, элемент `Manifest.files`.
  Типизирован, чтобы ключи контракта не расползались строками.
- **`ManifestError`** — единое исключение `from_json` на **любое** нарушение минимальной
  схемы (битый JSON, не объект, отсутствие обязательного ключа включая `run_id`, `files`
  не список, элемент без `path`, неверные типы). Наружу не утекают `KeyError`/`TypeError`/
  `ValueError`. Обработка порчи концентрируется в модуле, не дублируется по хранилищам;
  тихий пропуск порченого манифеста (застрявшее навсегда письмо) заменён громким отказом.
- **`Decision`** — enum из трёх: `DOWNLOAD_AND_DELIVER · DELIVER_ONLY · SKIP`.
  Нелегальное «скачал, но не доставил» непредставимо. Догон метки (`to_label`)
  **ортогонален** — всегда, гейтится `mark_processed`.
- **`decide(manifest: Manifest | None, run_id, overwrite) -> Decision`** — чистая
  свободная функция рядом с `Manifest`. Вся семантика ADR-0001 + `overwrite` в одном
  месте; `None` — валидный вход (нет манифеста / локальный режим).
- **`Window`** — чистый value-объект «временное окно поиска» (`window.py`). Владеет всей
  epoch/tz-математикой границ: `Window.resolve(ref_day, timezone, lookback_days,
  date_from, date_to)` → `.after_epoch() -> int | None`, `.before_epoch() -> int | None`
  (`after_epoch` — `None` в режиме диапазона только с `date_to`, ADR-0004). Выбор дня в
  зоне оператора (ADR-0002) и диапазон (ADR-0004) живут здесь; `build_query` лишь
  дописывает `after:`/`before:`, про таймзоны не зная. Сюда же стягиваются все off-by-one
  границы суток.
- **`Destination`-порт НЕ вводится** — шов хранилища остаётся наследованием
  (ADR-0006). Чтение манифеста — protected `_read_manifest(rel_dir) -> Manifest | None`
  на наследнике оператора.

## Метки (labels)

- **`mark_processed`** — независимая опция: вешает Gmail-метку на обработанные письма.
  local-оператор и Gmail-сенсор затем отсеивают такие письма, сравнивая `labelIds`
  письма с ID метки в коде (`find_label_id` → `exclude_label_id`), а **не** термом
  `-label:` в запросе. На корректность S3-дедупа не влияет (в S3 отсева по метке нет,
  ADR-0001); экономит вызовы. По умолчанию выключена (тогда хватает скоупа
  `gmail.readonly`).
