# ADR-0004: Явный диапазон дат (`date_from` / `date_to`) для ручного backfill

- **Статус:** Accepted
- **Дата:** 2026-07-11

## Контекст

Окно по `lookback_days` — только нижняя граница `after:`, заякоренная на `DagRun`.
Изолировать прошлый период (перекачать письма за конкретный день/диапазон, не задев
остальное) им нельзя: `after:` без верхней границы тянет `[start, ∞)`, а ручной триггер
якорит окно на «сейчас». Точечный backfill — редкая, но реальная нужда.

## Решение

Добавляются два **необязательных** параметра оператора: `date_from`, `date_to`.

- Гранулярность — **день**, интерпретация — в `timezone` оператора (не в зоне расписания
  DAG). `template_fields` — заполняются из `dag_run.conf` при ручном запуске.
- Если задан **хотя бы один** — режим явного диапазона; `lookback_days` **игнорируется**
  (WARNING, если он был не дефолтным):
  - `after:` = полночь `date_from` в `timezone` (если задан);
  - `before:` = полночь `(date_to + 1 день)` в `timezone` (если задан) — чтобы день
    `date_to` вошёл **целиком** (Gmail `before:` строго-меньше).
- Диапазон меняет только **когда** (окно). **Что** (сырой `query` / структурированные
  поля) и `-label:` остаются ортогональны.
- Партиция `dt=` не меняется — она датой **письма** (`internalDate`), не `date_from`/`date_to`.
- Штатное спаривание backfill: `overwrite=True` без `GmailAttachmentToS3Sensor`
  (сенсор увидел бы манифест и не пустил оператор).

## Consequences

- Теперь период изолируется явно; ручной триггер с заполненными датами перекачивает
  ровно `[date_from, date_to]` при `overwrite=True`.
- `before:` несёт **ту же ловушку границы суток, что ADR-0002**: наивный `before:date_to`
  (без `+1 день` и без учёта `timezone`) отрежет весь последний день. Правило `+1 день` и
  вычисление в `timezone` — обязательны, покрываются тестом.
- Оба бонусных параметра осмысленны и в базовом операторе, и в S3; в локальном режиме
  работают, но там дедупа нет — backfill там = просто перекачка за период.
- `date_from`/`date_to` — `template_fields` (заполняются из `conf`), поэтому строка
  парсится в дату и валидируется (`date_from ≤ date_to`) **в `execute()` после рендера**,
  не в `__init__`. Это обратный выбор к ADR-0005 (там паттерн не templated и компилируется
  в `__init__`): разница в том, что диапазон дат — по своей природе runtime-значение.
