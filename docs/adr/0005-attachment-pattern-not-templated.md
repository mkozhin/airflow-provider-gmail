# ADR-0005: `attachment_pattern` не templated, компилируется в `__init__`

- **Статус:** Accepted
- **Дата:** 2026-07-11

## Контекст

План (Task 7) требовал одновременно: компилировать `attachment_pattern` через
`re.compile` в `__init__` (ранняя ошибка на парсинге DAG) **и** включить его в
`template_fields`. Это несовместимо: `template_fields` рендерятся перед `execute()`,
перезаписывая атрибут, а `__init__` видит сырой шаблон. Компиляция в `__init__` пришлась
бы на строку с `{{ ... }}`, а отрендеренное значение осталось бы нескомпилированным —
тихий баг.

## Решение

`attachment_pattern` **не** входит в `template_fields`. Компилируется через `re.compile`
в `__init__` — кривая регулярка падает на разборе DAG, а не в рантайме.

Динамика имени (дата в имени файла) выражается **не** через шаблон в regex, а через:

- `filename_contains` → `filename:` (серверное сужение Gmail), и/или
- статический regex вида `^report_\d{8}\.xlsx$`.

## Consequences

- Ранняя валидация регулярки сохранена; паттерн детерминирован.
- Дату **в самом regex** подставить нельзя. Если такая нужда возникнет — это возврат к
  варианту (c) из грилинга (компиляция в `execute()` после рендера), с потерей ранней
  ошибки; пока не требуется.
- Будущим правкам: **не** возвращать `attachment_pattern` в `template_fields` без
  переноса компиляции в `execute()` — иначе тихий баг с сырым шаблоном.
