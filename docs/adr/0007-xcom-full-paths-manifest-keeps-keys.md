# ADR-0007: XCom доставки несёт полные пути; манифест остаётся на ключах

- **Статус:** Accepted
- **Дата:** 2026-07-21

## Контекст

Стыковка с `airflow-provider-tablefile` (и будущими потребителями) потребовала,
чтобы потребитель мог обратиться к доставленному манифесту, не зная бакет из
сторонних источников. До 0.3.0 XCom S3-оператора нёс голые object keys
(`prefix/dt=.../<message_id>/_manifest.json`) — адрес без хранилища.

Рассматривались четыре варианта: оставить голый ключ; полный URI
`s3://<bucket>/<key>`; URI с endpoint (`https://storage.yandexcloud.net/...`);
структурированная пара `(bucket, key)`. Отдельно стоял вопрос, менять ли заодно
`files[].path` внутри манифеста.

## Решение

XCom доставки — список **полных путей**: S3 → URI `s3://<bucket>/<key>`,
локальный оператор → абсолютный путь (как и раньше). URI **не несёт endpoint**:
он адресует объект только в паре с подключением потребителя (`aws_conn_id`),
endpoint хранилища живёт в connection.

Схема манифеста **не меняется**: `files[].path` остаётся S3-ключом или
абсолютным локальным путём. Полные URI вложений восстанавливает резолвер — по
бакету из URI самого манифеста.

Реализация — четвёртый protected-метод шва хранилища `_xcom_path(rel_path)`
(наследование, ADR-0006): базовый/локальный → `_destination_path`, S3 →
`s3://{bucket}/{key}`. Ломающее изменение, релиз 0.3.0 (потребителей старого
контракта не было).

## Обоснование

- `s3://bucket/key` — стандарт экосистемы. Ключи URL-безопасны **по
  построению**: sanitization имён вложений заменяет `? # %` и прочие
  «characters to avoid» из гайдлайна S3, а `prefix` валидируется оператором
  (решение 2026-07-21, codex-ревью плана). Поэтому URI корректно разбирается
  и стандартным `S3Hook.parse_s3_url`, и прямым разбиением строки; сам
  провайдер разбирает только собственным `split_s3_uri` (`utils/paths.py`)
  как защита в глубину против старых/чужих ключей.
- Endpoint в URI привязал бы **данные** к конкретному хранилищу и сломал
  `parse_s3_url`. Endpoint — свойство подключения, не адреса: смена хранилища
  (миграция, стейджинг) не должна инвалидировать исторические XCom.
- Пара `(bucket, key)` ломает симметрию с локальным оператором (строка-путь)
  и заставляет каждого потребителя собирать URI самому.
- Манифест — контракт слоя 2 и носитель дедупа (ADR-0001): его схема должна
  быть стабильнее XCom-контракта. Бакет однозначно восстанавливается из URI
  манифеста (все `files[].path` лежат в том же бакете), дублировать его в
  каждом `files[].path` незачем.

## Consequences

- Потребитель обязан иметь собственный `aws_conn_id`, указывающий на то же
  хранилище, что и у download-оператора; README фиксирует это как часть
  контракта.
- XCom и `files[].path` манифеста расходятся по источнику: XCom — только через
  `_xcom_path`, манифест — только через `_destination_path`. Менять
  `_destination_path` S3-оператора на URI нельзя (URI утёк бы в манифест);
  ветвление `isinstance`/`hasattr` в базовом `execute()` запрещено (ADR-0006).
- Будущим обзорам: **не** пере-предлагать «поменять и `files[].path` на URI
  для единообразия» — это ре-литигация; схема манифеста — контракт слоя 2.
